# EXP-04 — UNIQUE 제약을 제거하면 락 전략이 중복을 막아 주는가

```text
실험 이름: nounique / nouniqueopen — coupon_issue 의 UNIQUE(coupon_id, user_id) 를 DROP 한 뒤 EXP-02(쿠폰 100개)·EXP-07(재고 무제한) 과 같은 부하
검증하려는 가설: 중복 방지는 락 전략의 성질이 아니라 UNIQUE 제약의 성질이다. 제약이 없으면 조건부 UPDATE 도 같은 사용자에게 두 번 발급한다.
변경한 항목: ALTER TABLE coupon_issue DROP INDEX uk_coupon_user (실험 후 TRUNCATE + 재생성, SHOW INDEX 로 복구 확인). 전략은 락 없음·조건부 UPDATE 2종.
통제한 조건: EXP-02·EXP-07 과 동일 (1,000 VU, 사용자 1,000명 × 2회, 5회 반복, 순서 회전)
서버 및 DB 사양: EXP-01 과 동일
테스트 데이터: coupon 1행(total_quantity=100 또는 10,000,000), coupon_issue 0행, UNIQUE 없음
동시 사용자: 1,000
전체 요청 수: 2,000 × 2전략 × 5회 × 2조건 = 40,000건
테스트 지속시간: 요청 2,000건 소진까지 (0.6~2.5초)
```

## 측정 결과 (5회, 정합성 값은 최악)

쿠폰 100개 (EXP-02 조건):

| 구현 방식 | 성공 응답 | 409 | DB 발급 건수 | 고유 사용자(min) | 중복 발급(max) | 초과 발급(max) |
|---|---:|---:|---:|---:|---:|---:|
| 락 없음 | 2,000 | 0 | 2,000 | 1,000 | 1,000 | 1,900 |
| 조건부 UPDATE | 100 | 0 | 100 | 95 | **5** | 0 |

재고 무제한 (EXP-07 조건):

| 구현 방식 | 성공 응답 | 409 | DB 발급 건수 | 고유 사용자 | 중복 발급 (5회) |
|---|---:|---:|---:|---:|---:|
| 락 없음 | 2,000 | 0 | 2,000 | 1,000 | 1000, 1000, 1000, 1000, 1000 |
| 조건부 UPDATE | 2,000 | 0 | 2,000 | 1,000 | 1000, 1000, 1000, 1000, 1000 |

```text
병목 원인: 해당 없음(정합성 실험).
해석:
  제약을 빼면 조건부 UPDATE 도 재고가 남아 있는 한 같은 사용자에게 두 번 발급한다(2,000건 전부 성공, 중복 1,000). 재고 100개 조건에서도
  5회 중 1회, 같은 사용자의 두 요청이 품절 전에 동시에 들어와 5건이 중복됐다. 조건부 UPDATE 는 "재고 초과"만 막고 "같은 사용자 두 번"은 모른다.
  락 없음은 두 가지 모두 막지 못한다(중복 1,000 + 초과 1,900).
부작용: 애플리케이션에서 "이미 발급됐는지 SELECT 후 INSERT" 로 막으려 하면 그 사이의 경쟁 조건은 또 다른 락이 필요하다. 제약이 가장 싸고 확실하다.
결론: 가설 확인. 중복 발급 0건은 UNIQUE(coupon_id, user_id) 제약이 담당하며, 이 저장소의 모든 전략은 그 제약을 전제로 한다.
다음 실험: 없음(실험 후 제약 복구 확인: SHOW INDEX ... uk_coupon_user 존재).
```
